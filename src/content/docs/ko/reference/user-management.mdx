Tier0는 에디션에 따라 서로 다른 방식으로 사용자 권한과 접근을 관리합니다.
- Cloud는 Workspace 멤버 초대를 통해 Workspace에 접근할 수 있는 사용자를 관리합니다.
- Enterprise에서는 관리자가 사용자 계정과 역할을 할당하여 접근 가능한 기능을 결정합니다.

## 접근 제어
<Tabs syncKey="edition">
  <TabItem label="Cloud">

- Workspace 소유자 또는 기존 멤버는 전화번호나 이메일 주소를 통해 새 멤버를 초대할 수 있습니다.
- 새 멤버는 초대 코드 또는 링크를 받은 후 계정을 등록하고 Workspace에 참여합니다.
- 초대할 때 새 멤버의 시트 유형(Operator 또는 Builder)을 설정하여 접근할 수 있는 기능 범위를 결정합니다.

    - **Builder**: 모든 기능 모듈에 접근할 수 있습니다.
    - **Operator**: 애플리케이션 센터에만 접근할 수 있습니다.
- 계정 등록에는 2단계 확인이 필요합니다.

:::caution
Workspace 멤버 자격만으로 플랫폼 접근 권한이 자동으로 부여되지는 않습니다. 플랫폼을 사용하려면 초대를 받은 전화번호 또는 이메일 주소로 계정을 등록해야 합니다.
:::

:::note
계정을 등록한 후 새 Workspace를 신청할 수도 있습니다.
:::

  </TabItem>
  <TabItem label="Enterprise">

- 관리자는 기본 계정으로 처음 로그인한 후 비밀번호를 변경하고, **설정**에서 사용자 계정을 추가하고 역할을 할당합니다.
- 관리자는 계정을 할당하여 플랫폼을 사용할 수 있는 사용자를 결정하고, 역할을 할당하여 각 계정이 접근할 수 있는 기능을 결정합니다.

    - **Admin**: 모든 기능 모듈에 접근할 수 있습니다.
    - **Operator**: 접근 가능한 모든 애플리케이션이 나열된 **Launchpad**에만 접근할 수 있습니다.

:::note
관리자가 생성한 계정으로 로그인하고, 할당된 역할의 권한 범위 내에서 기능을 사용합니다.
:::
  </TabItem>
</Tabs>

## 계정 관리
<Tabs syncKey="edition">
  <TabItem label="Cloud">

| 작업 | 수행자 | 설명 |
| --- | --- | --- |
| 시트 유형 변경 | 생성자 / Builder | <ul><li>생성자는 모든 멤버의 시트 유형을 변경할 수 있습니다.</li><li>Builder는 Operator의 시트 유형만 변경할 수 있습니다.</li></ul> |
| Workspace 삭제 | 생성자 | Workspace를 삭제하면 모든 데이터가 즉시 삭제되며 복구할 수 없습니다. |
| Workspace 이전 | 생성자 | — |
| 멤버 제거 | 생성자 / Builder | <ul><li>생성자는 모든 멤버를 제거할 수 있습니다.</li><li>Builder는 Operator만 제거할 수 있습니다.</li></ul> |
| 계정 삭제 | 모든 멤버 | <ul><li>생성자는 먼저 Workspace를 삭제하거나 다른 멤버에게 이전해야 합니다.</li><li>계정 데이터는 즉시 삭제되며 복구할 수 없습니다.</li></ul> |

  </TabItem>
  <TabItem label="Enterprise">

- Admin은 비밀번호를 재설정하고, 사용자 역할을 수정하고, 계정을 비활성화하거나 삭제할 수 있습니다.
- 최초 기본 계정의 역할은 수정할 수 없으며, 해당 계정을 비활성화하거나 삭제할 수도 없습니다.
- 계정을 삭제하면 모든 데이터가 즉시 삭제되며 복구할 수 없습니다.

  </TabItem>
</Tabs>
