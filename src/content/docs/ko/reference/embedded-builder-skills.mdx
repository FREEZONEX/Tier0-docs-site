[Tier0 Builder Skills 저장소](https://github.com/FREEZONEX/Tier0-Builder-Skill/tree/feature/cloud-new-architecture-migration)의 `feature/cloud-new-architecture-migration` 브랜치에는 현재 요구사항, 앱 구축, 플랫폼 정렬, 브라우저 기능, 반응형 디자인, 미리보기 문제를 다루는 Skill 6개가 있습니다.

## `app-srs`

산업용 앱 요구사항 분석의 시작점입니다. 요청에서 SRS를 만들거나 PRD를 변환하고 기존 SRS를 수정합니다. 비즈니스 역할, 워크플로, 상태, 검증, 예외를 정리하고 첫 릴리스 범위를 정한 뒤 기본적으로 `specs/spec.md`에 저장합니다. 요구사항만 요청했거나 확인이 필요한 경우를 제외하고 새 앱을 `app-builder`로 이어서 처리합니다.

```text
$app-srs로 자동차 부품 공장의 품질 이상 관리 시스템을 설계해 줘.
```

## `app-builder`

요구사항이나 `specs/spec.md`를 바탕으로 실행 가능한 첫 앱을 만들거나 기존 앱에 큰 비즈니스 모듈을 추가합니다. 필요하면 `app-srs`로 SRS를 먼저 작성합니다. 일반적인 필드, 문구, 스타일, 단일 UI 수정에는 전체 Builder 절차가 필요하지 않습니다.

진입점과 실제 사용자 경로, 실제 데이터와 상태 변경, 검증과 역할 권한, 빌드·미리보기·대화형 흐름을 확인합니다. 적절한 목록 페이지에는 대상 스캐폴드의 `MetaListPage`를 실제 서비스와 권한에 연결합니다.

```text
$app-builder로 specs/spec.md의 첫 버전을 만들어 줘.
```

## `align-platform-app`

가져온 앱을 Tier0 스캐폴드로 마이그레이션하거나 기존 앱을 현재 계약에 맞춥니다. 이전 Tier0 앱, 앱 자체 SQL 데이터베이스·브라우저 저장소·모의 영속성을 쓰는 앱, 전체 업데이트나 제한적인 플랫폼 수정이 필요한 앱에 적합합니다.

[클라우드 아키텍처 스캐폴드](https://github.com/FREEZONEX/Tier0-App-Scaffold/tree/feature/cloud-new-architecture-migration)의 정확한 커밋과 비교합니다. 비즈니스 동작을 유지하면서 런타임, 라우팅, Gateway 역할, 플랫폼 계약을 맞춥니다. 전체 클라우드 마이그레이션에서는 `@tier0/sdk-v2`로 앱 소유 영속 레코드를 Tier0 UNS collections로 옮깁니다. 원래 데이터베이스의 과거 기록이 필요하다면 UNS로 별도로 가져와야 합니다. 변경된 빌드와 실행 동작을 검증한 후 `package.json`에 스캐폴드 버전을 기록합니다.

```text
$align-platform-app으로 비즈니스 코드를 유지하며 최신 Tier0 스캐폴드에 맞춰 줘.
```

:::caution
제한적인 수정은 전체 데이터 마이그레이션이나 스캐폴드 업데이트 완료를 의미하지 않습니다.
:::

## `browser-platform-capabilities`

QR/바코드 스캔, 사진 촬영, 위치 정보, 오디오 녹음, 파일 읽기, 클립보드 접근을 안내합니다. 대상 장치에 맞는 브라우저 API와 대체 수단을 선택하고 보안 컨텍스트, 권한, iframe/WebView 제한을 확인합니다. 취소나 실패 시 입력을 보존하고 대체 데이터가 실시간 캡처와 다르면 이를 표시합니다. 성공, 거부, 재시도, 정리를 검증합니다.

```text
$browser-platform-capabilities로 점검 양식에 사진 촬영과 파일 업로드 대안을 추가해 줘.
```

:::note
이 Skill은 통합 Tier0 장치 SDK를 제공하지 않으며 모든 브라우저나 임베디드 호스트에서 이러한 API가 허용된다고 보장하지 않습니다.
:::

## `responsive-craft`

복잡한 중단점, 연동되는 고정·스크롤 영역, 여러 화면 크기의 감사와 미리보기를 다룹니다. 개별 오버플로나 잘린 컨트롤은 직접 수정할 수 있습니다. `audit`는 기존 레이아웃 검사와 수리, `build`는 새 반응형 페이지 구축, `preview`는 여러 중단점의 실시간 미리보기입니다.

```text
$responsive-craft audit로 이 대시보드의 모바일 레이아웃을 수정해 줘.
```

```text
$responsive-craft preview로 375, 768, 1024, 1440 px를 보여 줘.
```

## `preview-runtime-stability`

관리형 미리보기의 설치, 시작, 준비 상태, 역할, 포트, HMR 문제를 진단합니다. 비즈니스 기능은 만들지 않습니다. 의존성·lockfile 오류, Vite/TanStack Start 시작 문제, `5173` 포트 충돌, `/api/health` 실패, 미리보기 역할, `artifact.toml` 불일치, 잦은 전체 페이지 새로고침을 다룹니다. 첫 관련 오류를 확인하고 증거가 있는 원인을 수정하며 필요할 때만 재시작한 뒤 원래 오류, 상태 검사, 해당 경로를 검증합니다.

```text
$preview-runtime-stability로 "Preview loading timed out"을 진단해 줘.
```

## Skill 선택 가이드

- 요구사항 작성·수정: `app-srs`; 새 앱은 보통 `app-builder`로 이어집니다.
- 첫 릴리스나 큰 비즈니스 확장: `app-builder`.
- 마이그레이션 또는 스캐폴드 정렬: `align-platform-app`.
- 여섯 가지 브라우저 기능: `browser-platform-capabilities`.
- 복잡한 반응형 작업: `responsive-craft`; 관리형 미리보기 오류: `preview-runtime-stability`.
