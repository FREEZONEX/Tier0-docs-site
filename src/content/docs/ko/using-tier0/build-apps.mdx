AI 대화를 통해 맞춤형 산업용 애플리케이션을 구축합니다. 애플리케이션은 공장 데이터를 사용할 수 있으며 역할 기반 접근 제어, 버전 관리, 배포 같은 기능을 기본으로 포함할 수 있습니다.

## Tier0 앱 구축하기
애플리케이션을 구축하기 전에 project 를 생성합니다.

- Project 는 애플리케이션을 분류하고 애플리케이션 접근 권한을 관리하는 데 사용됩니다.
- 하나의 project 안에 있는 애플리케이션들은 복잡한 시스템의 관련 기능 모듈처럼 구성될 수 있습니다.
- 각 project 의 데이터는 다른 project 의 데이터와 독립적입니다.

### Prompt 작성
Agent 가 요구 사항에 더 잘 맞는 애플리케이션을 생성할 수 있도록 prompt 에는 ***최소한*** 다음 내용을 포함해야 합니다.

- **애플리케이션 목적**: 이 애플리케이션의 목적은 무엇인가요?
    ```text
    공장 기술자를 위한 설비 유지보수 애플리케이션을 생성합니다.
    ```
- **애플리케이션 데이터**: 애플리케이션은 어떤 데이터를 사용하며, 그 데이터는 어디에 있나요?

    <Tabs>
    <TabItem label="Platform Plan">
    Prompt 에 UNS topic 을 명시하면 애플리케이션은 UNS 에서 데이터를 소비하고 UNS 로 데이터를 게시할 수 있습니다.
    ```text
    이 애플리케이션은 xxx UNS model 의 설비 상태, 알람 기록, 유지보수 이력을 사용하고, 업데이트를 xxx UNS topic 으로 게시해야 합니다.
    ```
    </TabItem>
    <TabItem label="Builder Plan">
    애플리케이션은 UNS 에 연결되지 않습니다. 애플리케이션 사용 중 생성되는 데이터는 데이터베이스에 저장됩니다.
    </TabItem>
    </Tabs>
- **애플리케이션 기능**: 애플리케이션은 무엇을 해야 하나요?
    ```text
    이 애플리케이션은 사용자가 설비 상태를 모니터링하고, 유지보수 요청을 제출하며, 수리 진행 상황을 추적할 수 있어야 합니다.
    ```

:::caution[**Builder** 를 사용하는 경우]
**Builder** plan 은 현재 UNS 를 지원하지 않지만, 시뮬레이션 데이터는 사용할 수 있습니다. 더 구체적인 데이터 통합 요구 사항이 있으면 sales@freezonex.io 로 문의하세요.
:::
:::tip[애플리케이션을 더 빠르게 구축하기]
- 일반적인 산업용 애플리케이션 템플릿은 **Library** 에 제공됩니다. 템플릿을 사용하고 그 위에서 기능을 수정하면 애플리케이션을 훨씬 빠르게 구축할 수 있습니다.
- [내장 Builder Skills](../../reference/embedded-builder-skills/)를 사용해 애플리케이션 구축을 지원할 수 있습니다.
- 대화가 너무 길어지면 `/clear` 로 컨텍스트를 비우고, `/compact` 로 컨텍스트를 압축하세요.
:::

### 접근 제어
역할 기반 접근 제어는 projects 와 애플리케이션 모두에 적용됩니다.

- Project access levels
    - **Owner**: project 에 대한 전체 접근 권한입니다.
    - **Can Edit**: project 삭제를 제외한 전체 접근 권한입니다.
    - **Can Launch**: **Launchpad** 에서 project 를 보고 허용된 애플리케이션만 사용할 수 있습니다.
- Application roles
    - 명시적으로 정의하지 않은 경우 애플리케이션의 비즈니스 로직에 따라 agent 가 자동 생성합니다. 책임 범위가 일치하면 다른 애플리케이션의 기존 역할을 재사용할 수 있습니다.
    - Project 멤버에게만 할당할 수 있습니다.
    - Prompt 에 역할이 필요 없다고 명시하면 애플리케이션은 모든 project 멤버에게 열립니다.

:::tip[직접 역할을 지정하려는 경우]
Prompt 에 역할과 권한 범위를 명시하세요. Agent 는 이를 다른 애플리케이션에서 생성된 기존 역할과 비교합니다. 충돌이 있으면 agent 가 확인을 요청합니다.
:::
:::caution[역할로 제어되는 애플리케이션에는 애플리케이션 역할 할당이 필수입니다]
**Launchpad** 에서 역할로 제어되는 애플리케이션에 접근하려면 애플리케이션 역할이 반드시 할당되어야 합니다. Workspace/project owner 라도 애플리케이션 역할이 없으면 해당 애플리케이션에 접근할 수 없습니다.
:::

### 버전 관리
Tier0 에서 애플리케이션은 3가지 상태로 존재합니다.

- **Draft**: 애플리케이션의 최신 상태입니다. 배포하지 않으면 이 버전의 변경 사항은 다른 버전에 영향을 주지 않습니다.
- **Snapshot**: snapshot 생성 시점의 애플리케이션을 저장합니다. Snapshot 버전을 배포하면 현재 **Active** 버전이 교체됩니다.
- **Active**: 현재 온라인으로 실행 중인 애플리케이션 버전입니다.

:::tip[버전 전환]
- Draft 를 배포하면 active 애플리케이션이 더 새로운 버전으로 업데이트됩니다.
- Snapshot 을 배포하면 active 애플리케이션이 이전 버전으로 롤백됩니다.
:::

### 외부로 내보내기
애플리케이션이 준비되면 **Preview** 페이지에서 외부 타사 환경 또는 Tier0 Enterprise 용으로 내보낼 수 있습니다.

- **Download Source Code**: 2차 개발을 위해 애플리케이션 소스 코드를 내보냅니다.
- **Export Bundle**: **Tier0 Enterprise** 에서 로컬로 가져오기 위한 전용 내보내기입니다.

:::tip[Snapshot 소스 코드 다운로드]
Snapshot 을 저장한 후 다운로드하면 해당 snapshot 버전의 소스 코드를 받을 수 있습니다.
:::
