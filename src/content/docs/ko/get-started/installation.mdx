Tier0는 세 가지 edition으로 사용할 수 있습니다.
- **Edge** - 단일 machine 또는 Docker에서 직접 실행합니다.
- **Cloud** - 운영 인프라가 필요 없는 managed SaaS입니다.
- **Enterprise** - enterprise environment를 위한 private deployment입니다.

어떤 edition을 선택해야 할지 확실하지 않다면 [최적의 버전 선택](../choosing-version/)을 먼저 확인하세요.

## Tier0 설치

<Tabs syncKey="edition">
  <TabItem label="Cloud">

    Tier0 Cloud는 설치가 필요하지 않습니다. signup 후 workspace를 만들면 됩니다.
    <Steps>
    1. [Register Tier0](https://tier0.dev/signup)에서 계정을 만듭니다.
    2. email confirmation을 완료하고 login page로 돌아갑니다.
    3. **Login** button을 클릭해 계정에 로그인합니다.
    4. 기본 정보를 입력하고 **Continue**를 클릭합니다.
    5. **Create a New Workspace**를 선택합니다.
    6. workspace를 만들고 Cloud 환경을 사용합니다.
    </Steps>

  </TabItem>
  <TabItem label="Edge">

    #### 요구사항
    - 최소 4-core CPU, 8 GB RAM, 100 GB disk
    - Docker와 Git이 설치된 Ubuntu 24.04 또는 Windows 10/11

    #### 설치
    <Steps>
    1. GitHub에서 Tier0-Edge repository를 서버에 clone하고 project로 이동합니다.

        ```bash
        git clone https://github.com/FREEZONEX/Tier0-Edge
        cd Tier0-Edge/deploy
        ```

    2. 배포 전에 `.env.default`에서 필요한 environment parameter를 수정합니다.

        ```bash
        vi .env.default
        :wq!
        ```
        :::note[설정 가능한 parameters]

        | Field | Type | Description | Example |
        |------|------|-------------|---------|
        | VOLUMES_PATH | string | project data 저장 경로 | Linux에서는 `/srv/tier0/data`, Windows Bash에서는 `D:/tier0/data` 또는 `/d/tier0/data` |
        | ENTRANCE_DOMAIN/ENTRANCE_PORT | string | Tier0 access endpoint(IP/domain + port) | `192.168.1.10` / `8088` |
        | LANGUAGE | enum | zh-CN / en-US | `en-US` |
        | ADMIN_INIT_PASSWORD | string | admin user initial password | 안전한 private password |
        | COMPOSE_PROJECT_NAME/PORT_OFFSET | string | 같은 host에서 실행되는 여러 instance를 격리 | `edge_lab` / `100` |

        :::
    3. install script를 실행하고 installation status를 확인합니다.

        ```bash
        bash bin/install.sh
        bash bin/compose.sh ps # container status 확인
        bash bin/compose.sh logs -f backend # backend container log 확인
        curl -fsS http://127.0.0.1:8088/readyz # backend service readiness 확인
        ```

        :::caution
        `deploy/.env.runtime`는 수정하지 마세요. 생성된 secrets와 resolved runtime values가 포함되어 있습니다.
        :::
    4. 설정한 endpoint와 기본 admin account로 Tier0에 접속합니다.
        - Username: `tier0`
        - Password: `.env.default`의 `ADMIN_INIT_PASSWORD` 값. 설정하지 않았다면 `tier0`.

    </Steps>

  </TabItem>
  <TabItem label="Enterprise">

    #### 요구사항
    - Standard Deployment
      - 최소: 4 VMs
      - VM resource 권장:
        - App: 8C / 32G / 100G
        - Database: 4C / 8G / 500G
        - Witness: 2C / 4G / 40G
    - High Availability Deployment
      - 최소: 6 VMs
      - VM resource 권장:
        - App (Swarm): 8C / 32G / 100G x 3
        - Database: 4C / 8G / 500G x 2
        - Witness: 2C / 4G / 40G

    :::tip[구체적인 requirements는 deployment scenario에 따라 달라질 수 있습니다]
    Enterprise hardware requirements는 deployment scenario에 따라 달라질 수 있습니다.
    :::

    :::note
    표준 deployment topology는 [High Availability Deployment Plan](../../reference/high-availability-deployment/)을 확인하세요.
    :::

    #### 설치
    <Steps>
    1. package를 control host에 복사하고 검증합니다.
        ```bash
        sha256sum -c tier0-enterprise-offline-standard-YYYYmmddTHHMMSS.tar.gz.sha256
        ```
    2. package를 압축 해제합니다.
        ```bash
        tar -xzf tier0-enterprise-offline-standard-YYYYmmddTHHMMSS.tar.gz
        cd tier0-enterprise-offline-standard-YYYYmmddTHHMMSS
        ```
    3. deployment detail에 맞게 `install.env`를 수정한 뒤 deployment를 시작합니다.
        ```bash
        vi install.env
        bash install.sh
        ```
    </Steps>

    #### 유용한 운영 command
    - Enterprise 설치 전 deployment configuration을 점검합니다.
        ```bash
        ./install.sh --check-only
        ```
    - 실패한 deployment 후 모든 node를 정리합니다.
        ```bash
        ./full-cleanup.sh --env install.env --yes
        ```
        > 이 command는 VM, operating system, installation package, Docker software는 유지하지만 Tier0 runtime data와 database backup을 삭제합니다.
    - 설치 후 deployment report가 생성됩니다.
        ```text
        runtime/install-reports/<timestamp>/deployment-report.md
        ```
        > report에 **FAIL** 항목이 있으면 project를 공유하기 전에 먼저 support에 문의하세요.

  </TabItem>
</Tabs>
