## 安装 Tier0 Skills

请选择与你的环境匹配的安装方式。

### 有 Node.js

如果环境中有 Node.js 16 或更高版本，可以使用 `npx` 安装 CLI 和 skills。

```bash
npx -y @tier0/cli@latest install
```

该命令会运行完整安装器，并完成两件事：

- 将 `tier0` CLI binary 安装到 `~/.tier0/bin/`。
- 安装内置的 Tier0 Skill 基线，并同步到检测到的 agents，例如 Codex、Claude Code 和 Cursor。

### 没有 Node.js

<Steps>
1. 安装 `tier0` CLI binary。
    <Tabs syncKey="tier0-cli-binary-install">
      <TabItem label="curl">

        ```bash
        curl -fsSL https://raw.githubusercontent.com/FREEZONEX/Tier0-cli/main/install.sh | bash
        ```

      </TabItem>
      <TabItem label="iwr">

        ```powershell
        iwr https://raw.githubusercontent.com/FREEZONEX/Tier0-cli/main/install.ps1 | iex
        ```

      </TabItem>
    </Tabs>
2. 下载最新 Tier0 Skills，并同步到检测到的 agents。
    ```bash
    tier0 skills update
    ```
3. 验证已安装的 Skill 版本和健康状态。
    ```bash
    tier0 skills status
    ```
</Steps>

### 管理 Skills
- 检查已安装 Skill 的版本和健康状态：
    ```bash
    tier0 skills status
    ```
- 修复缺失或损坏的内置 Skill 基线：
    ```bash
    tier0 skills install
    ```
- 更新到最新 Tier0 Skill：
    ```bash
    tier0 skills update
    ```

## 用 Agents 操作 Tier0

### 设置操作实例
:::note
Cloud 默认使用 `https://tier0.dev`，无需配置 base URL。
:::
私有化部署必须在登录前配置 base URL。配置完成后，后续所有命令都会在该实例上执行。

```bash
tier0 config --base-url https://your-tier0.example.com
tier0 login # interactive browser login
```

### 认证

<Tabs syncKey="tier0-login-method">
  <TabItem label="已有 API 密钥">

  <Steps>
  1. 设置你从当前 Tier0 实例获取的 API 密钥。

      ```bash
      tier0 config --api-key <api-key>
      ```
  2. 验证 API 密钥身份和权限。
      ```bash
      tier0 auth whoami --json
      ```
  3. 使用 `tier0` CLI 执行其他操作。
  </Steps>

  </TabItem>
  <TabItem label="没有 API 密钥">

  <Steps>
  1. 获取浏览器认证链接。

      ```bash
      tier0 login --no-wait --json
      ```
  2. 访问返回的 `verification_url`，在浏览器中完成认证。
  3. 使用返回的 `setup_code` 轮询登录结果。
      ```bash
      tier0 login --setup-code <setup_code>
      ```
 </Steps>
  </TabItem>
</Tabs>

:::caution[重要]
在配置 API 密钥或开始浏览器登录前，先运行 `config` 设置操作实例；否则 CLI 可能会操作到错误实例。
:::

### 预览操作
使用 `--dry-run` 验证并预览支持的写入操作，不向 Tier0 发送请求。

#### 支持的操作
- UNS：`write/create/update/delete/restore`
- Flow：`create/update/delete/deploy`

#### 示例
```bash
tier0 uns write --topic demo --value '{"value":1}' --dry-run
tier0 flow deploy --id 1 --flows-file flows.json --dry-run --json
tier0 api /openapi/v1/uns/write --body-file body.json --dry-run --json
```
:::note
`--json` 选项会以 JSON 格式输出请求。
:::
:::caution[请求 body 必须包含有效 JSON]
如果没有提供有效 JSON，CLI 不再猜测或重写格式错误的 JSON。
:::
#### 返回的预览

:::note
dry-run 输出不会泄露 headers 和 API keys。
:::

```json
{
  "ok": true,
  "dry_run": true,
  "data": {
    "api": [
      {"method": "POST", "url": "https://tier0.dev/openapi/v1/uns/write", "body": {}}
    ]
  }
}
```

### 处理错误
使用 `--json` 时，命令失败会返回包含错误消息和错误代码的 JSON object。

```json
{"ok":false,"error":{"type":"validation","subtype":"invalid_argument","param":"--qos","message":"--qos must be 0, 1, or 2"}}
```

## 卸载 CLI 和 Skills

- 卸载命令
```bash
# 移除 Tier0 CLI，但保留本地配置和 skills。
npx @tier0/cli@latest uninstall

# 移除 Tier0 CLI，并删除本地配置、凭证和缓存，但保留 skills。
npx @tier0/cli@latest uninstall --purge

# 移除 skills
npx @tier0/cli@latest uninstall --remove-skills

# 移除以上所有内容
npx @tier0/cli@latest uninstall --purge --remove-skills
```
- 全局 NPM 卸载
```bash
npm uninstall -g @tier0/cli
```
- 手动清理
```bash
rm -rf ~/.tier0/bin/tier0 ~/.tier0/skills
npx -y --package=skills -- skills remove tier0 -y -g
```
