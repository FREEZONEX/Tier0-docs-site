通过 AI 对话构建自定义工业应用。应用可以使用工厂数据，并提供基于角色的访问控制、版本管理和外部部署能力。

## 构建 Tier0 应用

- 文件夹仅用于归类应用。
- 系统会根据你的 Prompt 自动匹配模板，以节省开发时间。
- 设备管理、生产监控、能源管理等通用工业应用已有模板 Prompt。

### 编写 Prompt

说明应用的目标、功能及是否需要外部数据。

- **应用目标**：应用的用途是什么？
```text
为工厂技术人员创建一个设备维护应用。
```
- **应用功能**：应用需要做什么？
```text
允许用户监控设备状态、提交维护请求并跟踪维修进度。
```
- **应用数据**：应用是否需要外部数据？
```text
应用应使用 xxx collection 中的报警记录和维护历史。
```

:::note
- 应用启动所需的模拟数据会在 **Namespace** 中生成和建模。
- 外部数据需要由 Agent 接入，并在 **Namespace** 中建模。
:::

:::tip[更快构建应用]
- 在 **Library** 中使用常见工业应用模板，再按需修改功能。
- 使用[内置 Builder Skills](../../reference/embedded-builder-skills/)协助构建。
- 对话过长时，使用 `/clear` 清空上下文，或使用 `/compact` 压缩上下文。
:::

### 访问控制

应用采用基于角色的访问控制（RBAC），管理成员访问和允许执行的操作。

- 如果没有明确指定角色，Agent 会根据业务逻辑自动生成；也可复用其他应用中职责相符的角色。
- 应用角色只能分配给 Workspace 成员。
- 如果 Prompt 明确说明不需要角色，应用会向所有成员开放。

:::tip[自行指定角色]
在 Prompt 中说明角色和权限范围。Agent 会与其他应用的现有角色比较；如有冲突，会向你确认。
:::

:::caution[受角色控制的应用必须分配应用角色]
要在 **Launchpad** 中访问此类应用，必须分配应用角色。即使 Workspace 所有者没有应用角色，也无法访问。
:::

### 版本管理

- **未发布**：应用的最新状态；未部署的修改不会影响其他版本。
- **快照**：保存创建时的应用状态；部署快照会替换当前在线版本。
- **已发布**：当前在线版本。

部署未发布版本会更新在线应用；部署快照会回滚到较早版本。快照列在应用预览页面中。

### 导出到外部

应用准备就绪后，可从 **Preview** 页面导出至第三方环境或 Tier0 Enterprise。

- **下载源代码**：用于二次开发。
- **导出 Bundle**：用于在 **Tier0 Enterprise** 本地导入。

如需某个快照版本的源代码，先保存快照，再下载该快照。
