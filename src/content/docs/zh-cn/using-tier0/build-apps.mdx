通过 AI 对话构建自定义工业应用。应用可以使用工厂数据，并内置基于角色的访问控制、版本管理和外部部署等能力。

## 构建 Tier0 应用
构建应用前，请先创建一个项目。

- 项目用于归类应用，并管理应用访问权限。
- 同一个项目中的应用可以作为一个复杂系统中的功能模块单独存在。
- 每个项目中的数据彼此独立。

### 编写 Prompt
为了让 agent 生成更符合需求的应用，请确保 prompt ***至少*** 覆盖以下内容。

- **应用目标**：这个应用的目的是什么？
    ```text
    为工厂技术人员创建一个设备维护应用。
    ```
- **应用数据**：应用使用什么数据，数据在哪里？

    <Tabs>
    <TabItem label="Platform 套餐">
    [连接数据到 UNS](../connect-data/)，并在 prompt 中说明 UNS topic。
    ```text
    该应用应使用 xxx UNS 模型库中的设备状态、报警记录和维护历史数据。
    ```
    </TabItem>
    <TabItem label="Builder 套餐">
    Agent 会在初始化时自动模拟启动所需的数据。
    </TabItem>
    </Tabs>
- **应用功能**：应用需要做什么？
    ```text
    该应用应允许用户监控设备状态、提交维护请求，并跟踪维修进度。
    ```

:::caution[当你使用 **Builder** 套餐时]
**Builder** 套餐目前不支持 UNS，但可以使用模拟数据。如需更具体的数据集成能力，请通过 sales@freezonex.io 联系我们。
:::
:::tip[更快构建应用]
- 常见工业应用模板已提供在 **模板库** 中。你可以基于模板继续修改功能，从而更快构建应用。
- 使用 [内置 Builder Skills](../../reference/embedded-builder-skills/) 帮助构建应用。
:::

### 访问控制
项目和应用都采用了基于角色的访问控制。

- 项目角色
    - **可编辑**：拥有项目的完整访问权限，但不能删除项目。
    - **可启动**：只能在 **应用中心** 中看到该项目，并使用已被授权的应用。
- 应用角色
    - 由 agent 根据应用的业务逻辑自动生成。
    - 只有先被添加为项目成员后，才能分配应用角色。

:::tip[如果你想自行指定角色]
请在 prompt 中说明角色和权限范围，agent 会将其与自动生成的角色进行比较。当你的角色与生成的角色冲突时，agent 会向你确认。
:::
:::caution[必须分配应用角色]
要访问应用，必须分配应用角色。即使是项目所有者，如果没有应用角色，也无法在 **应用中心** 中看到该应用。
:::

### 版本管理
应用在 Tier0 中有 3 种状态。

- **草稿**：应用的最新状态。如果没有部署，对该版本的修改不会影响其它版本。
- **快照**：保存创建快照时的应用状态。部署快照版本会替换当前 **启用** 版本。
- **启用**：当前在线运行的应用版本。

:::tip[版本切换]
- 部署草稿时，启用应用会更新到较新的版本。
- 部署快照时，启用应用会回滚到较早的版本。
:::

### 导出到外部
应用准备好后，可以在 **预览** 页面导出，用于外部第三方环境或 Tier0 Enterprise。

- **下载源代码**：导出应用源代码，用于二次开发。
- **导出运行包**：专门用于在 **Tier0 Enterprise** 本地导入。
