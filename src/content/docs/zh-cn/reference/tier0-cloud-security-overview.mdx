**适用范围：** Tier0 云服务版生产 SaaS 服务，部署于 AWS 新加坡区域。\
**文档日期：** 2026 年 10 月 22 日

Tier0 云服务版通过网络访问控制、租户隔离、身份权限管理、数据加密及备份恢复等措施，降低网络攻击和未经授权访问的风险。本说明介绍平台的安全防护措施，以及限制安全事件向其他租户、平台内部服务和客户网络扩散的控制边界。

:::note[Edge 版本]
本说明仅适用于 Tier0 云服务版。Edge 的安装说明请参阅[安装](../../get-started/installation/)。
:::

## 1 网络边界与访问控制

Tier0 云服务版面向公网的 Web 与 API 访问采用 TLS 加密，并通过统一的边缘入口和应用网关接入平台。核心服务入口配置源站访问校验，对不符合校验要求的直接访问请求予以拒绝，降低绕过边缘入口访问源站的风险。

生产环境与开发、预发布环境在云账号、网络、集群和数据库等层面实施隔离，并分别管理访问凭据。生产管理访问通过经过身份认证的专用网络通道进行。

## 2 租户隔离与攻击扩散控制

### 2.1 工作负载隔离

租户工作负载运行在独立的 Kubernetes 命名空间中，并通过专用节点池和调度约束，与平台服务及管理组件分离。该机制用于限制租户应用与平台组件之间的直接接触范围，降低单个应用发生安全事件时对其他服务的影响。

### 2.2 网络隔离

租户命名空间的入站和出站通信采用默认拒绝、显式放行的网络策略。策略由平台自动配置并同步，由集群网络组件执行。

入站通信仅向同租户工作负载及承担必要业务功能的平台服务开放。出站通信按规则开放集群域名解析、同租户服务、指定平台网关、消息服务及所分配的数据库端点。公网访问受网络策略约束；除明确放行的业务依赖外，策略限制对私有网络地址的访问，并阻断对云实例元数据地址的直接访问。

上述措施用于限制未经授权的跨租户连接，以及从租户工作负载向平台内部网络的横向移动。单个租户应用发生安全事件，不会因此自动获得访问其他租户或平台管理组件的权限。已获授权的业务连接仍受相应网络规则和身份权限约束。

### 2.3 数据与身份隔离

租户应用数据在数据库层面实施逻辑隔离。分配独立数据库单元的场景，同时通过网络访问规则限制连接来源。

平台按服务职责配置访问权限，将工作负载的资源访问范围限定于所需功能。网络隔离与身份授权共同限制受影响工作负载能够访问的资源范围。

### 2.4 客户网络接入边界

本节所述租户隔离措施适用于 Tier0 云服务版平台内部。客户通过连接器、网关或其他集成方式接入内部系统时，客户网络的访问边界还取决于实际接入方式、路由、防火墙规则及所授予的凭据权限。

客户接入时应仅开放业务必需的目标地址、端口和账户权限，并对接入组件与其他内部系统实施网络分区。平台内部隔离不能替代客户侧的网络访问控制；双方应结合具体接入方案确定并核验访问范围，以限制经由已授权连接向客户其他系统扩散的风险。

## 3 数据保护

平台对数据传输、存储和访问实施相应保护：

- 公网 Web 与 API 通信，以及对托管数据库和缓存的访问，采用 TLS 加密。
- 托管数据库、缓存及对象存储启用静态加密。
- 对象存储配置公共访问阻断，并通过加密要求、HTTPS 访问要求和资源权限限制数据访问。
- 租户数据访问同时受数据库隔离和身份权限控制约束。

## 4 备份与恢复

Tier0 云服务版对生产数据库及纳入备份范围的服务级数据库执行备份，备份数据存储于专用、访问受限的对象存储中，并按相应保留策略管理。

备份任务使用独立身份，权限限定于指定存储位置所需的读写操作，不授予备份对象删除权限。备份到期清理由存储生命周期规则执行，以减少备份任务凭据泄露后被用于删除恢复数据的风险。

备份完成后执行完整性校验，并通过隔离环境中的恢复验证检查备份可用性。应用配置纳入版本控制，构建产物保存在私有镜像仓库，为服务恢复和版本回退提供支持。

## 5 管理访问与生产变更

生产管理访问使用具名身份，并按最小权限原则分配授权。涉及敏感操作的控制台身份实施强制多因素认证。

日常巡检使用受限的只读身份，可查看工作负载状态、日志和事件，不能读取敏感凭据、修改资源或执行远程命令。生产变更通过单独授权的身份和流程执行。

基础设施配置、部署清单和运维脚本纳入版本控制。生产变更需明确目标、影响范围、验证步骤和回滚方案，并记录执行身份、配置差异及验证结果，以支持追溯和恢复。

## 6 监控与安全事件处置

平台集中采集生产环境的运行指标、日志和健康状态，并将异常告警发送至运维响应渠道。监控范围包括服务可用性、错误率、数据库健康、证书有效期、备份任务状态及集群运行状态。

发生安全事件时，处置工作以控制影响范围为优先，并保留相关日志、配置和事件时间线。在完成必要的隔离与排查后恢复服务，随后开展事件复盘并跟踪整改。事件处置期间的生产变更按既定流程授权和留痕。

## 7 安全联系

有关安全评估、客户尽调或疑似漏洞，请联系 Tier0 客户经理或安全团队。涉及非公开的架构与控制细节，可在适当的保密安排下提供。首次联系时，请勿发送访问凭据、私钥或客户敏感数据。
