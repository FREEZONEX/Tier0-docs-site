Tier0 supports connecting to various industrial protocols, including OPC UA, Modbus, MQTT and more.

:::tip
We recommend using the agent to connect external data sources when no confidential authentication is required.
:::
## Connecting Data Sources
### OPC UA
- Security configuration is automatically obtained from the server once you enter the server address.
- Authentication is supported through username/password or certificate.
```json
{
  "name": "ua",
  "description": "",
  "protocol": "opcua",
  "endpoint": "opc.tcp://220.184.175.73:4841/demo/",
  "runtimeLocation": "local",
  "opcua": {
    "securityMode": "None",
    "securityPolicy": "None"
  }
}
```
### Modbus
Only server address and unit ID are required.
```json
{
  "name": "modbus",
  "description": "",
  "protocol": "modbus-tcp",
  "endpoint": "tcp://220.184.175.73:1502",
  "runtimeLocation": "local",
  "modbus": {
    "unitId": 1
  }
}
```
### MQTT
Tier0 can be used as an MQTT broker to receive data from devices, or as a client to connect to an external MQTT broker.

- As a broker:

    <Steps>
        1. Generates connection credentials including client ID, username and password when connecting <b>MQTT Device</b>.
        2. Third-party client must use the publish topic displayed on the connection panel to publish messages.
        3. Use the agent to build a stream, with the publish topic as input, to send data to the secified <b>Namespace</b>.
    </Steps>

- As a client: Connect third-party broker.
    ```json
    {
    "name": "111",
    "description": "",
    "protocol": "mqtt",
    "endpoint": "mqtt://220.184.175.73:1883",
    "runtimeLocation": "local",
    "mqtt": {
        "clientId": "tier0UxxxxxxxxuwQVfi"
    }
    }
    ```
### HTTP
Tier0 can be used as an HTTP server for third-party to access, or as a client to call API from other HTTP server.
- As a server:

    <Steps>
        1. Add an HTTP server in Tier0, and get the full address from the information panel.
        2. Use the agent to build a stream that defines data and subsequent routing, together forming an API.
        3. Third-party uses the address and the set routing to call the API and get the data.
    </Steps>

- As a client: Connect third-party HTTP servers.
```json
{
  "name": "222",
  "description": "",
  "protocol": "http-api",
  "endpoint": "http://220.184.175.73:8088/api/telemetry",
  "runtimeLocation": "local",
  "role": "client",
  "http": {
    "authentication": "none"
  }
}
```
### SQL Server
- Database address must include both port and database name.
- An initial query command is necessary.
- When the database is available for anonymous connection, authentication can be skipped.

```json
{
  "name": "eee",
  "description": "",
  "protocol": "edge-sql",
  "endpoint": "mysql://hzoffice.tier0.dev:3307/demo_factory",
  "runtimeLocation": "local",
  "sql": {
    "queries": {
      "query1": "SELECT * FROM telemetry ORDER BY id DESC LIMIT 5"
    },
    "tlsMode": "verify-full"
  },
  "credentialRef": "ref_9ce47b8778xxxxxxxx7dad49a86dbad"
}
```
### Github
<Steps>
1. Connect to Tier0 Github through OAuth.
2. Discover resources in this organization on the source information panel.
3. Ask the agent to build a stream to get needed data.
</Steps>
## Getting Data from Sources
:::note
Sources are only connections to the server, data acquisition and processing are handled by **Stream**.
:::
<Steps>
1. Ask the agent to build streams to get data from the connected sources.
2. Necessary information, such as Modbus registers, database queries, UA namespace URIs, MQTT topics are required in the prompt.
</Steps>
