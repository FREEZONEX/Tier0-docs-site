import { Tabs, TabItem } from '@astrojs/starlight/components';

Tier0 では、エディションごとに異なる方法でユーザー権限とアクセスを管理します。
- Cloud では、Workspace へのメンバー招待によって、誰が Workspace にアクセスできるかを管理します。
- Enterprise では、管理者がユーザーアカウントとロールを割り当て、アクセスできる機能を決定します。

## アクセス制御
<Tabs syncKey="edition">
  <TabItem label="Cloud">

- Workspace のオーナーまたは既存のメンバーは、電話番号またはメールアドレスを使って新しいメンバーを招待できます。
- 新しいメンバーは、招待コードまたは招待リンクを受け取った後、アカウントを登録して Workspace に参加します。
- 招待時に新しいメンバーのシート種別（Operator または Builder）を設定し、利用できる機能の範囲を決めます。

    - **Builder**：すべての機能モジュールにアクセスできます。
    - **Operator**：アプリケーションセンターにのみアクセスできます。
- アカウント登録には 2 段階の確認が必要です。

:::caution
Workspace のメンバー資格を得ても、プラットフォームへのアクセスが自動的に付与されるわけではありません。プラットフォームを利用するには、招待を受けた電話番号またはメールアドレスでアカウントを登録する必要があります。
:::

:::note
アカウント登録後、新しい Workspace を申請することもできます。
:::

  </TabItem>
  <TabItem label="Enterprise">

- 管理者はデフォルトのアカウントで初めてサインインした後、パスワードを変更し、**設定**でユーザーアカウントを追加してロールを割り当てます。
- 管理者は、アカウントの割り当てによってプラットフォームを利用できるユーザーを決定し、ロールの割り当てによって各アカウントがアクセスできる機能を決定します。

    - **Admin**：すべての機能モジュールにアクセスできます。
    - **Operator**：アクセス可能なすべてのアプリケーションが一覧表示される **Launchpad** にのみアクセスできます。

:::note
管理者が作成したアカウントでサインインし、割り当てられたロールの権限内で機能を利用します。
:::
  </TabItem>
</Tabs>

## アカウント管理
<Tabs syncKey="edition">
  <TabItem label="Cloud">

| 操作 | 実行できるユーザー | 説明 |
| --- | --- | --- |
| シート種別の変更 | 作成者 / Builder | <ul><li>作成者はすべてのメンバーのシート種別を変更できます。</li><li>Builder は Operator のシート種別のみ変更できます。</li></ul> |
| Workspace の削除 | 作成者 | Workspace を削除すると、すべてのデータが直ちに消去され、復元できません。 |
| Workspace の移譲 | 作成者 | — |
| メンバーの削除 | 作成者 / Builder | <ul><li>作成者はすべてのメンバーを削除できます。</li><li>Builder は Operator のみ削除できます。</li></ul> |
| アカウントの削除 | すべてのメンバー | <ul><li>作成者は先に Workspace を削除するか、ほかのメンバーに移譲する必要があります。</li><li>アカウントデータは直ちに消去され、復元できません。</li></ul> |

  </TabItem>
  <TabItem label="Enterprise">

- Admin はパスワードのリセット、ユーザーロールの編集、アカウントの無効化、アカウントの削除を行えます。
- 初期デフォルトアカウントのロールは編集できず、このアカウントを無効化または削除することもできません。
- アカウントを削除すると、すべてのデータが直ちに消去され、復元できません。

  </TabItem>
</Tabs>
