[Tier0 Builder Skills リポジトリ](https://github.com/FREEZONEX/Tier0-Builder-Skill/tree/feature/cloud-new-architecture-migration)の `feature/cloud-new-architecture-migration` ブランチには現在、要件、アプリ構築、プラットフォーム整合、ブラウザー機能、レスポンシブ設計、プレビュー障害に対応する 6 つの Skill があります。

## `app-srs`

産業向けアプリの要件定義の入口です。依頼から SRS を作成し、PRD を変換し、既存の SRS を改訂します。業務上の役割、ワークフロー、状態、検証、例外を整理し、初回リリースの範囲を定め、既定で `specs/spec.md` に保存します。要件だけが求められた場合や確認が必要な場合を除き、新規アプリは `app-builder` に引き継ぎます。

```text
$app-srs を使って自動車部品工場の品質異常管理システムを設計してください。
```

## `app-builder`

要件または `specs/spec.md` から動作する初回アプリを構築するか、既存アプリに大きな業務機能を追加します。必要なら先に `app-srs` で SRS を作成します。通常のフィールド、文言、スタイル、局所的な UI 修正には完全な Builder ワークフローは不要です。

機能の入口と操作経路、実データと状態変更、検証とロール権限、ビルド・プレビュー・対話操作を確認します。適切な一覧ページでは対象スキャフォールドの `MetaListPage` を実際のサービスと権限に接続します。

```text
$app-builder を使って specs/spec.md から初回バージョンを構築してください。
```

## `align-platform-app`

インポートしたアプリを Tier0 スキャフォールドへ移行するか、既存アプリを現在の契約に合わせます。古い Tier0 アプリ、独自 SQL データベースやブラウザー保存を使うアプリ、全面更新または限定的なプラットフォーム修正が必要なアプリが対象です。

[クラウドアーキテクチャのスキャフォールド](https://github.com/FREEZONEX/Tier0-App-Scaffold/tree/feature/cloud-new-architecture-migration)の正確なコミットと比較し、業務動作を保ちながらランタイム、ルーティング、Gateway ロール、プラットフォーム契約を合わせます。クラウドへの全面移行では、アプリ独自の永続レコードを `@tier0/sdk-v2` で Tier0 UNS collections に移します。元のデータベースにある履歴レコードが必要なら、UNS 側へ別途インポートします。ビルドと実行時の動作を検証してから `package.json` にスキャフォールドのバージョンを記録します。

```text
$align-platform-app を使い、業務コードを維持して最新の Tier0 スキャフォールドに合わせてください。
```

:::caution
限定的な修正は、データ移行やスキャフォールド更新の完了を意味しません。
:::

## `browser-platform-capabilities`

QR／バーコード読み取り、写真撮影、位置情報、録音、ファイル読み取り、クリップボードを扱います。対象デバイスに適したブラウザー API と代替手段を選び、安全なコンテキスト、権限、iframe／WebView の制約を確認します。キャンセルや失敗時にはフォーム入力を保持し、代替データがライブ取得と異なる場合はその違いを明示します。成功、拒否、再試行、後片付けを検証します。

```text
$browser-platform-capabilities を使って点検フォームに写真撮影とファイルアップロードの代替手段を追加してください。
```

:::note
この Skill は統一された Tier0 デバイス SDK を提供せず、すべてのブラウザーや組み込みホストで API が使えることも保証しません。
:::

## `responsive-craft`

複雑なブレークポイント、連動する固定・スクロール領域、複数画面幅での監査とプレビューを扱います。単純なはみ出しや切れた操作部品は直接修正できます。`audit` は既存レイアウトの監査と修正、`build` は新規構築、`preview` は複数幅のライブプレビューです。

```text
$responsive-craft audit を使ってダッシュボードのモバイルレイアウトを修正してください。
```

```text
$responsive-craft preview で 375、768、1024、1440 px を表示してください。
```

## `preview-runtime-stability`

管理されたプレビューのインストール、起動、準備状態、ロール、ポート、HMR の障害を診断します。業務機能は構築しません。依存関係・ロックファイルのエラー、Vite／TanStack Start の起動、`5173` の競合、`/api/health`、プレビューのロール、`artifact.toml`、HMR の全ページ再読み込みなどが対象です。最初の関連エラーを読み、確認できた原因を修正し、必要な場合だけ再起動して、元の障害、ヘルスチェック、対象ルートを検証します。

```text
$preview-runtime-stability を使って「Preview loading timed out」を調査してください。
```

## Skill 選択ガイド

- 要件の作成・改訂：`app-srs`。新規アプリは通常 `app-builder` に引き継ぎます。
- 初回リリース・大きな業務機能追加：`app-builder`。
- 移行・スキャフォールド整合：`align-platform-app`。
- 6 種類のブラウザー機能：`browser-platform-capabilities`。
- 複雑なレスポンシブ設計：`responsive-craft`。管理されたプレビューの障害：`preview-runtime-stability`。
