Tier0 は、次の 2 つの側面からデータの安全性を確保します。

- **セキュリティ**：プラットフォーム、アプリケーション、データにアクセスできるユーザーを制御します。
- **レジリエンス**：障害発生後のサービス継続とデータ復旧に対応します。

## エディションごとのセキュリティ範囲

| エディション | セキュリティの範囲 |
| --- | --- |
| **Cloud** | プラットフォームへのアクセス制御と、認証が必要な MQTT および API へのアクセスを提供します。 |
| **Enterprise** | プラットフォームとデータへのアクセス制御に加え、プライベート環境向けのデプロイの可用性、バックアップ、復旧を提供します。 |
| **Edge（オープンソース）** | ローカルでのデータ接続とモデリングに使用します。内蔵 MQTT ブローカーは認証なしのサブスクリプションを許可します。 |

各エディションの位置付けについては、[最適な製品の選択](https://tier0.app/pricing)を参照してください。

:::note[Tier0 Cloud のセキュリティに関する説明]
Cloud の本番サービスにおけるネットワーク境界、テナント分離、データ保護、セキュリティ運用については、[Tier0 Cloud のネットワークとデータのセキュリティに関する説明](../../reference/tier0-cloud-security-overview/)を参照してください。この説明は Tier0 Cloud のみに適用されます。
:::

## セキュリティ

### ID とアクセス制御

| 対象 | Tier0 の仕組み | 詳細 |
| --- | --- | --- |
| プラットフォームへのアクセス | <ul><li>Cloud は Workspace のメンバー資格でアクセスを制御します。</li><li>Enterprise はユーザーアカウントでアクセスを制御します。</li></ul> | [ユーザー管理](../../reference/user-management/) |
| Agent のアクセス | Agent は API キーで認証し、Tier0 CLI を使用してプラットフォームにアクセスして操作します。 | [CLI 認証](../../using-tier0/operating-on-tier0-with-agents/#認証) |
| プロジェクトとアプリケーションへのアクセス | Tier0 は RBAC を使用してアプリケーションへのアクセスを制御します。 | [アクセス制御](../../using-tier0/building-apps/#アクセス制御) |

:::note
Workspace のメンバー資格によってアカウントが自動作成されることはありません。ユーザー自身がアカウントを登録してサインインする必要があります。アカウント登録には 2 段階の確認が必要です。
:::

### データアクセス制御

| アクセス方法 | Tier0 の仕組み | 詳細 |
| --- | --- | --- |
| MQTT | <ul><li>クライアントは Tier0 が生成した認証情報で認証します。</li><li>TLS とセキュア WebSocket が転送中のデータを暗号化します。</li></ul> | [MQTT 認証情報と接続](../../using-tier0/working-with-factory-data/#mqtt-credentials-を生成する) |
| REST API | データへのアクセスには Tier0 が生成したキーが必要です。 | [API リファレンス](../../reference/api-reference/) |

## レジリエンス

### デプロイの可用性

Enterprise は現在、センターノード向けに 2 つのデプロイ計画を提供しています。

| 計画 | 可用性の境界 | 詳細 |
| --- | --- | --- |
| **標準デプロイ** | <ul><li>データベースのプライマリ／スタンバイのフェイルオーバーに対応します。</li><li>Enterprise アプリケーションと EMQX は単一障害点として残ります。</li></ul> | [標準デプロイ計画](../../reference/standard-deployment-plan/) |
| **高可用デプロイ** | <ul><li>Enterprise のアクティブ／スタンバイノードを追加し、データベース、キャッシュ、オブジェクトストレージ、管理対象のランタイムファイルのフェイルオーバー動作を定義します。</li><li>無停止やデータ損失ゼロを保証するものではありません。</li></ul> | [高可用デプロイ計画](../../reference/high-availability-deployment-plan/) |

:::note
可用性の制限の詳細は、[SLA と高可用性の境界](../../reference/sla-and-ha-boundaries/)を参照してください。
:::

### バックアップと復旧

Enterprise はデータベースのバックアップと復旧を提供します。復旧後はデプロイ状態を確認し、基本機能を検証して、プラットフォームにサインインできることを確認してください。

- バックアップについては、[バックアップと復元](../../reference/operations-runbook/#backup-and-restore)を参照してください。
- 復旧検証の要件については、[SLA と高可用性の境界](../../reference/sla-and-ha-boundaries/)の訓練要件を参照してください。

:::note[応答時間]
通常の応答時間は 3 営業日です。
:::
