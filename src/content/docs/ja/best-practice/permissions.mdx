---
title: RBAC アクセス制御
editions: [cloud, enterprise]
---

Tier0 は、**ワークスペースのシート**でプラットフォーム機能を、**ビジネスロール**でアプリ内のアクセスを制御する、2 層のロールベースアクセス制御（RBAC）を使用します。

:::note[Edge エディション]
RBAC アクセス制御は Cloud と Enterprise で利用できます。Edge では、独自のデプロイ環境でアクセスを管理します。
:::

## ワークスペースのシート

### ワークスペースのシートとは

メンバーのシートは **Builder** と **Operator** の 2 種類です。

:::note
- ワークスペースのオーナーも **Builder** です。
- **Builder** と **Operator** はどちらもワークスペースのメンバーです。
:::

| 種類 | 権限 |
| --- | --- |
| オーナー | ワークスペースの全機能を使用でき、請求、全メンバー、所有権の譲渡、ワークスペースの削除を単独で管理します。 |
| Builder | オーナー専用機能を除くすべてのワークスペース機能を使用できます。 |
| Operator | アクセス権のあるアプリを使用します。 |

### シートの割り当て方法

- ワークスペースへの招待時にメンバーのシートを設定します。
- 既存メンバーのシートは **Settings** > **Member** で変更できます。

:::note
各シートの数は契約プランによって制限されます。詳しくは[最適な製品の選択](../../get-started/choosing-the-best-product/)を参照してください。
:::

## ビジネスロール

### ロールの作成方法

- アプリのロールは業務ロジックに基づいて自動生成されます。
- プロンプトでロールが不要と明示した場合は生成されません。
- Agent は確認を得てから、他のアプリで同様の責務を持つ既存ロールを再利用できます。

### ロールの割り当て方法

- ロールはメンバーまたはメンバーグループに割り当てられます。
- メンバーは複数のグループに所属し、直接割り当てとグループからの継承によって複数のロールを持てます。
- 別の割り当てが残っている場合、1 つの割り当てを削除してもロールは取り消されません。

### 権限の範囲

- ロールを持つメンバーは、そのロールを使用するすべてのアプリにアクセスできますが、許可された部分に限られます。
- ワークスペースのシートはビジネスロールに影響しません。**Builder** でもアプリへのアクセス権は自動的に付与されません。
- アプリ生成中のロールのプレビューは開発用です。
- ロールのないアプリは、ワークスペースのすべての有効なメンバーが利用できます。

:::note[注意事項]
- フォルダーはアプリの整理にのみ使われ、アクセス権を付与しません。
- メンバーのシートを変更するとプラットフォーム権限は変わりますが、ビジネスロールは維持されます。
- ワークスペースからメンバーを削除すると、ワークスペースとすべてのアプリへのアクセスが取り消されます。
:::
