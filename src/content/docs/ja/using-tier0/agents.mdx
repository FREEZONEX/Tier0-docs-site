## Skills と CLI のインストール

環境に合うインストーラーを選択します。

### Node.js がある場合

Node.js 16 以降が利用できる場合は、`npx` で CLI と skills をインストールします。

```bash
npx -y @tier0/cli@latest install
```

このコマンドは完全なインストーラーを実行し、次の 2 つを行います。

- `tier0` CLI binary を `~/.tier0/bin/` にインストールします。
- 組み込みの Tier0 Skill baseline をインストールし、Codex、Claude Code など検出された agents に同期します。

### Node.js がない場合

<Steps>
1. `tier0` CLI binary をインストールします。
    <Tabs syncKey="tier0-cli-binary-install">
      <TabItem label="curl">

        ```bash
        curl -fsSL https://raw.githubusercontent.com/FREEZONEX/Tier0-cli/main/install.sh | bash
        ```

      </TabItem>
      <TabItem label="iwr">

        ```powershell
        iwr https://raw.githubusercontent.com/FREEZONEX/Tier0-cli/main/install.ps1 | iex
        ```

      </TabItem>
    </Tabs>
2. 最新の Tier0 Skills をダウンロードし、検出された agents に同期します。
    ```bash
    tier0 skills update
    ```
3. インストール済み Skill のバージョンと health を確認します。
    ```bash
    tier0 skills status
    ```
</Steps>

### Skills の管理
- インストール済み Skill のバージョンと health を確認します。
    ```bash
    tier0 skills status
    ```
- 欠落または破損した組み込み Skill baseline を修復します。
    ```bash
    tier0 skills install
    ```
- 最新の Tier0 Skill に更新します。
    ```bash
    tier0 skills update
    ```

## Skills と CLI の連携
Tier0 CLI は実行可能なコマンドを提供し、Skills は agents がそれらのコマンドを選択して安全に使うためのガイドを提供します。
:::note
Tier0 Skills は prompt によって自動的に起動され、agents に何をすべきか、どのコマンドを使うべきかを案内するように設計されています。
:::

### 例
- Prompt：`Plant/Line1/Metric/Temperature` の現在温度を確認します。
- Skill
  - `tier0-uns`
  - 現在値は完全な topic path から読み取る必要があることを agent に伝え、適切な UNS read 操作を選択します。
- CLI：`tier0 uns read Plant/Line1/Metric/Temperature --json`

### Skills
| Skill | 目的 |
| --- | --- |
| `tier0` | Tier0 タスクを適切な skill にルーティングし、共通のセットアップ、認証、安全ルールを提供します。 |
| `tier0-uns` | Browse、read、write、history、search、create、update、delete、restore などの UNS 操作を agents に案内します。 |
| `tier0-flow` | SourceFlow と EventFlow の管理を agents に案内します。これには確認、エクスポート、作成、更新、デプロイ、削除が含まれます。 |
| `tier0-mqtt` | MQTT 認証情報の管理、publish、範囲を限定したリアルタイム subscribe を agents に案内します。 |
| `tier0-files` | Upload、download、アクセス URL 生成、delete などの Tier0 ファイル操作を agents に案内します。 |

:::tip[agent に skill repo を読ませる]
詳細については、agent に [Tier0 Skill repo](https://github.com/FREEZONEX/Tier0-Skills) を読ませてください。
:::

## CLI 操作

### 操作対象インスタンスの設定
:::note
Cloud はデフォルトで `https://tier0.dev` を使用するため、base URL の設定は不要です。
:::
プライベートデプロイでは、ログイン前に base URL を設定する必要があります。設定後、以降のすべてのコマンドはそのインスタンスで実行されます。

```bash
tier0 config --base-url https://your-tier0.example.com
tier0 login # interactive browser login
```

### 認証

<Tabs syncKey="tier0-login-method">
  <TabItem label="API key がある場合">

  <Steps>
  1. 操作対象の Tier0 インスタンスから取得した API key を設定します。

      ```bash
      tier0 config --api-key <api-key>
      ```
  2. API key の identity と permissions を確認します。
      ```bash
      tier0 auth whoami --json
      ```
  3. `tier0` CLI で他の操作を実行します。
  </Steps>

  </TabItem>
  <TabItem label="API key がない場合">

  <Steps>
  1. ブラウザー認証リンクを取得します。

      ```bash
      tier0 login --no-wait --json
      ```
  2. 返された `verification_url` にアクセスし、ブラウザーで認証を完了します。
  3. 返された `setup_code` でログイン結果を確認します。
      ```bash
      tier0 login --setup-code <setup_code>
      ```
 </Steps>
  </TabItem>
</Tabs>

:::caution[重要]
API key の設定やブラウザーログインを開始する前に、`config` を実行して操作対象インスタンスを設定してください。そうしないと、CLI が誤ったインスタンスを操作する可能性があります。
:::

### 操作のプレビュー
`--dry-run` を使用すると、対応する書き込み操作を Tier0 に送信せずに検証およびプレビューできます。

#### 対応操作
- UNS: `write/create/update/delete/restore`
- Flow: `create/update/delete/deploy`
- API: `tier0 api`
- MQTT: `auth create/auth delete/publish`
- Files: `delete`

#### 例
```bash
tier0 uns write --topic demo --value '{"value":1}' --dry-run
tier0 flow deploy --id 1 --flows-file flows.json --dry-run --json
tier0 api /openapi/v1/uns/write --body-file body.json --dry-run --json
tier0 mqtt auth create --name my-client --save my-client --dry-run --json
tier0 assets delete --file-path workspace/path/to/file.csv --dry-run --json
```
:::note
`--json` オプションはリクエストを JSON 形式で出力します。
:::
:::caution[request body には有効な JSON が必要です]
有効な JSON が提供されていない場合、CLI は不正な JSON を推測したり書き換えたりしません。
:::
#### 返されるプレビュー

:::note
dry-run 出力では headers と API keys は表示されません。
:::

```json
{
  "ok": true,
  "dry_run": true,
  "data": {
    "api": [
      {"method": "POST", "url": "https://tier0.dev/openapi/v1/uns/write", "body": {}}
    ]
  }
}
```

### エラー処理
`--json` を使用すると、コマンド失敗時にエラーメッセージとコードを含む JSON object が返されます。

```json
{"ok":false,"error":{"type":"validation","subtype":"invalid_argument","param":"--qos","message":"--qos must be 0, 1, or 2"}}
```

## Skills と CLI のアンインストール

- アンインストールコマンド
```bash
# Tier0 CLI を削除し、local configuration と skills は保持します。
npx @tier0/cli@latest uninstall

# Tier0 CLI を削除し、local configuration、credentials、cache を削除しますが、skills は保持します。
npx @tier0/cli@latest uninstall --purge

# skills を削除します
npx @tier0/cli@latest uninstall --remove-skills

# 上記すべてを削除します
npx @tier0/cli@latest uninstall --purge --remove-skills
```
- Global NPM アンインストール
```bash
npm uninstall -g @tier0/cli
```
- 手動クリーンアップ
```bash
rm -rf ~/.tier0/bin/tier0 ~/.tier0/skills
npx -y --package=skills -- skills remove tier0 -y -g
```
