AI との対話でカスタム産業アプリを構築します。アプリは工場データを利用でき、ロールによるアクセス制御、バージョン管理、外部へのデプロイ機能を備えます。

## Tier0 アプリを構築する

- フォルダーはアプリの分類にのみ使用します。
- プロンプトに応じてテンプレートが自動的に選ばれ、開発時間を短縮します。
- 設備管理、生産監視、エネルギー管理などの一般的な産業アプリにはテンプレートプロンプトがあります。

### プロンプトを書く

アプリの目的、機能、外部データが必要かどうかを示します。例：

```text
工場技術者向けの設備保全アプリを作成し、状態監視、保全依頼、修理状況の追跡を可能にしてください。
xxx collection のアラーム記録と保全履歴を使ってください。
```

:::note
- アプリの起動に使う模擬データは **Namespace** で生成・モデル化されます。
- 外部データは Agent が接続し、**Namespace** でモデル化する必要があります。
:::

:::tip[アプリをより速く構築するには]
- **Library** の産業アプリテンプレートを使い、必要に応じて機能を変更します。
- [組み込み Builder Skills](../../reference/embedded-builder-skills/)を利用します。
- 会話が長くなったら `/clear` でコンテキストを消去するか、`/compact` で圧縮します。
:::

### アクセス制御

アプリはロールベースアクセス制御（RBAC）でメンバーのアクセスと操作を管理します。

- 明示されない場合、Agent が業務ロジックからロールを生成します。責務が合う既存ロールも再利用できます。
- アプリのロールは Workspace メンバーにのみ割り当てられます。
- ロール不要とプロンプトで明示したアプリは、すべてのメンバーに開放されます。

:::tip[独自のロールを指定する場合]
プロンプトにロールと権限範囲を記します。Agent は他のアプリの既存ロールと比較し、競合時は確認します。
:::

:::caution[ロール制御されたアプリにはロール割り当てが必須]
**Launchpad** でアクセスするにはアプリのロールが必要です。Workspace の所有者でも、ロールがなければアクセスできません。
:::

### バージョン管理

- **未公開**: アプリの最新状態。デプロイ前の変更は他のバージョンに影響しません。
- **スナップショット**: 保存時点の状態。デプロイすると現在の公開バージョンに代わります。
- **公開済み**: 現在オンラインのバージョン。

未公開バージョンをデプロイすると最新版に更新され、スナップショットをデプロイすると以前の状態に戻ります。スナップショットはアプリのプレビューページに表示されます。

### 外部へエクスポート

完成したアプリは **Preview** ページから外部環境や Tier0 Enterprise 向けにエクスポートできます。

- **ソースコードをダウンロード**: 二次開発向け。
- **Bundle をエクスポート**: **Tier0 Enterprise** でのローカルインポート向け。

スナップショットのソースコードが必要なら、保存後にそのスナップショットをダウンロードします。
