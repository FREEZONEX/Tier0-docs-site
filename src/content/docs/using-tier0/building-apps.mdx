Build customized industrial applications through AI conversations. Applications can use factory data 
and include built-in capabilities such as role-based access control, version management, and external deployment.

## Building a Tier0 App

- Folder is used to categorize applications only.
- Templates will be automatically matched and used based on your prompt to save development time.
- Template prompt is available for general industrial applications, such as equipment management, production monitoring, and energy management.

### Writing Prompt
Make sure your prompt covers the following aspects for the agent to generate an application that better fits your requirements.
- **Application Purpose**: What is the purpose of the application?
    ```text
    Create an equipment maintenance application for factory technicians.
    ```
- **Application Function**: What does the application do?
    ```text
    The application should allow users to monitor equipment conditions, submit maintenance requests, and track repair progress.
    ```
- **Application Data**: Does the application need external data?

    :::note
    - Simulated data for application startup will be generated and modeled in the **Namespace**.
    - External data will need to be connected and modeled in the **Namespace** by the agent.
    :::
    ```text
    The application should use alarm records and maintenance history from the xxx collection.
    ```

:::tip[To build applications faster]
- Templates of common industrial applications are provided in **Library**. You can use a template and change features on top to build an application much faster.
- Use the [embedded Builder skills](../../reference/embedded-builder-skills/) to help build applications.
- Use `/clear` to clear context and `/compact` to compress context when the conversation is too long.
:::
### Access Control
Applications adopt role-based access control (RBAC) to manage member access and allowed actions.
- Roles are automatically generated by the agent based on business logic of the application when not explicitly defined. Existing roles from other applications may be reused when their responsibilities align.
- Can only be assigned to workspace members.
- The application is open to all members if the prompt explicitly specifies that no roles are required.

:::tip[If you want to assign your own roles]
State the roles and permission scope in the prompt, and the agent will compare them with existing roles generated from other applications. If there is a conflict, the agent will confirm with you.
:::
:::caution[Application role assignment is a **MUST** for role-controlled applications]
To access a role-controlled application in **Launchpad**, you must have application roles assigned. Even a workspace owner cannot access the application without an application role.
:::

### Version Management
Applications exist on Tier0 in 3 shapes.
- **Unpublished**: The latest state of the application. Changes on this version will not affect other versions if not deployed.
- **Snapshot**: Saves the application at the time of taking the snapshot. Deploying a snapshot version takes down the current **Active** version.
- **Published**: The current online version of the application.

:::tip[Version switch]
- Deploy a draft, the active application updates to a newer version.
- Deploy a snapshot, the active application rolls back to an earlier version.
:::
:::note
Snapshots are listed inside the application preview page.
:::

### Export to External
Once the application is ready, you can export it from the **Preview** page for external third-party environments or Tier0 Enterprise.
- **Download Source Code**: Export source code of the application for secondary development.
- **Export Bundle**: Specifically exported for local import on **Tier0 Enterprise**.

:::tip[Download the source code of a snapshot]
Download a snapshot after saving it to get the source code of that snapshot version.
:::
