Data in Tier0 unified namespace can be altered and managed through MQTT and APIs with authorization.

## MQTT
MQTT clients can connect to the UNS broker with credentials generated on Tier0.
:::note
You can use MQTT clients such as **MQTTX**, **MQTT Explorer**, and **Node-RED** to connect to the broker and publish/subscribe messages.
:::
### Generating MQTT Credentials
Generate MQTT credentials in **Connect** > **Source** > **MQTT Device** and make a note of it.
:::note[Exceptions on Tier0 Edge version]
The Tier0 Edge version does not require credentials for external connections.
:::
### Connecting MQTT Clients

:::tip
- The UNS broker can be connected through both TCP and WSS with the following address:
    - mqtt://host:1883
    - mqtts://host:8883
    - ws://host:8083/mqtt
    - wss://host:8084/mqtt
- TCP without TLS is used as an example in the following connections.
:::

<Tabs syncKey="mqtt-client">
  <TabItem label="MQTTX">

1. Install and open <a href="https://mqttx.app/" target="_blank" rel="noopener noreferrer">MQTTX</a>.
2. Add a connection with the information of the UNS broker and the generated credentials.
    ```json
    {
      "Host": "mqtt.tier0.dev",
      "Port": 1883,
      "Client ID": "<generated client ID>",
      "Username": "<generated username>",
      "Password": "<generated password>"
    }
    ```

  </TabItem>
  <TabItem label="MQTT Explorer">

1. Install and open <a href="https://mqtt-explorer.com/" target="_blank" rel="noopener noreferrer">MQTT Explorer</a>.
2. Add a new connection with the UNS broker information and the generated credentials.
    ```json
    {
      "Protocol": "mqtt://",
      "Host": "mqtt.tier0.dev",
      "Port": 1883,
      "Username": "<generated username>",
      "Password": "<generated password>"
    }
    ```
3. Change the client ID to the credential ID in **ADVANCED** before connecting.

  </TabItem>
  <TabItem label="Node-RED">
      - Use **Event Flow** - Data processing module in Tier0 based on Node-RED.

          1. Create an **Event Flow** in **Flows**, and start it with an `mqtt in` node.
          2. Select the UNS broker as **Server** (same name as the flow) and set **Topic** to a UNS model in the node.

      - Use **Independent Node-RED Instance**

          1. Install and open the <a href="https://nodered.org/docs/getting-started/local" target="_blank" rel="noopener noreferrer">Node-RED</a> instance.
          2. Add a server in the `mqtt in` node with the following information.
          ```json
          {
            {/* under Connection */}
            "Server": "mqtt://mqtt.tier0.dev",
            "Port": 1883,
            "Client ID": "<generated clientId>",
            {/* under Security */}
            "Username": "<generated username>",
            "Password": "<generated password>"
          }
          ```
  </TabItem>
</Tabs>

### Testing Connections
<Steps>
1. Make sure the client status is normal.
2. Copy a UNS model topic and publish a message to it through the client.
</Steps>

## API

### Basic Information

- **Base URL**: `https://<your-tier0-host>/openapi/v2`
- **Authentication**: Send the API key obtained from Tier0 in the `x-api-key` header.

### Request Examples

- `POST /uns/metadata:find` — List collections and get the collection ID
  :::note
  Find the collection you want in `data.items` and copy its `id`. If it is missing from the first page, check `data.pageInfo` and request the next page.
  :::
  <Tabs syncKey="uns-api-language">
    <TabItem label="JavaScript">

  ```js
  const base = "https://your-tier0-host/openapi/v2";
  const response = await fetch(`${base}/uns/metadata:find`, {
    method: "POST",
    headers: { "content-type": "application/json", "x-api-key": "your-api-key" },
    body: JSON.stringify({"kind": "collection", "filter": {}, "page": {"mode": "offset", "page": 1, "size": 20}}),
  });
  const result = await response.json();
  if (!response.ok || result.code !== 0) throw new Error(result.error?.code || result.msg);
  console.log(result.data.items);
  ```

    </TabItem>
    <TabItem label="Python">

  ```python
  import requests

  response = requests.post(
      "https://your-tier0-host/openapi/v2/uns/metadata:find",
      headers={"x-api-key": "your-api-key"},
      json={"kind": "collection", "filter": {}, "page": {"mode": "offset", "page": 1, "size": 20}},
      timeout=30,
  )
  response.raise_for_status()
  result = response.json()
  if result["code"] != 0:
      raise RuntimeError(result.get("error", result.get("msg")))
  print(result["data"]["items"])
  ```

    </TabItem>
    <TabItem label="cURL">

  ```bash
  curl --fail-with-body -X POST "https://your-tier0-host/openapi/v2/uns/metadata:find" \
    -H "content-type: application/json" \
    -H "x-api-key: your-api-key" \
    -d '{"kind": "collection", "filter": {}, "page": {"mode": "offset", "page": 1, "size": 20}}'
  ```

    </TabItem>
  </Tabs>

- `POST /uns/collections/{collectionId}/records:find` — List records and get the record ID
  :::note
  - Replace `your-collection-id` with the ID from `metadata:find`.
  - Find the target record in `data.items` and copy its `id`. If it is missing from the first page, use `data.pageInfo.nextCursor` as the `cursor` in the next request when available.
  :::
  <Tabs syncKey="uns-api-language">
    <TabItem label="JavaScript">

  ```js
  const base = "https://your-tier0-host/openapi/v2";
  const collectionId = "your-collection-id";
  const response = await fetch(`${base}/uns/collections/${encodeURIComponent(collectionId)}/records:find`, {
    method: "POST",
    headers: { "content-type": "application/json", "x-api-key": "your-api-key" },
    body: JSON.stringify({"limit": 20}),
  });
  const result = await response.json();
  if (!response.ok || result.code !== 0) throw new Error(result.error?.code || result.msg);
  console.log(result.data);
  ```

- `POST /uns/collections/{collectionId}/samples:find` — Get samples in a time range
  :::note
  - Replace `your-collection-id` with the ID from `metadata:find`.
  - Replace `record_123` in `recordIds` with the record ID from `records:find`.
  - Set `from` and `to` to the time range you want.
  - This example also filters on `temperature`. Remove that filter if you want all samples in the range or if your collection uses a different field.
  :::
  <Tabs syncKey="uns-api-language">
    <TabItem label="JavaScript">

  ```js
  const base = "https://your-tier0-host/openapi/v2";
  const collectionId = "your-collection-id";
  const response = await fetch(`${base}/uns/collections/${encodeURIComponent(collectionId)}/samples:find`, {
    method: "POST",
    headers: { "content-type": "application/json", "x-api-key": "your-api-key" },
    body: JSON.stringify({"recordIds": ["record_123"], "from": 1792454400000, "to": 1792540800000, "filter": {"temperature": {"$gt": 20}}, "limit": 20}),
  });
  const result = await response.json();
  if (!response.ok || result.code !== 0) throw new Error(result.error?.code || result.msg);
  console.log(result.data);
  ```

    </TabItem>
