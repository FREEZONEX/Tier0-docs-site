Tier0 ships in three editions:
- **Cloud** - Managed SaaS, no infrastructure required.
- **Enterprise** - Private deployment for enterprise environments.
- **Edge** - Open-source, runs locally with Docker.

See [Choosing the Best Version](../choosing-version/) to find the edition that best fits your requirements.


## Installing Tier0

<Tabs syncKey="edition">
	<TabItem label="Cloud">

		Apply for a trial account before exploring Tier0 Cloud.
		<Steps>
		1. Register your account at [Register Tier0](https://tier0.dev/signup). 
		2. Use the verification code sent to your email to verify and then log in with the registered account.
		3. Create a workspace and start your trial.
	</Steps>

	<TabItem label="Enterprise">
#### Requirements
-  Standard Deployment
	- Minimum: 4 VMs
	- Required baseline per VM types:
		- App: 8C / 32G / 100G
		- Database: 4C / 8G / 500G
		- Witness: 2C / 4G / 40G
-  High Availability Deployment
	- Minimum: 6 VMs
	- Required baseline per VM types:
		- App (Swarm): 8C / 32G / 100G x 3
		- Database: 4C / 8G / 500G x 2
		- Witness: 2C / 4G / 40G

:::tip[Hardware requirements may vary]
Enterprise hardware requirements vary by deployment scenarios.
:::

:::note
Detailed deployment information is available in the [High Availability Deployment Plan](../../reference/high-availability-deployment/).
:::
#### Operations
<Steps>
1. Get the package from your vendor, and verify it.
		```bash
		sha256sum -c tier0-enterprise-offline-standard-YYYYmmddTHHMMSS.tar.gz.sha256
		```
2. Decompress the package.
		```bash
		tar -xzf tier0-enterprise-offline-standard-YYYYmmddTHHMMSS.tar.gz
		cd tier0-enterprise-offline-standard-YYYYmmddTHHMMSS
		```
3. Edit `install.env` based on the deployment details, then start the deployment.
		```bash
		vi install.env
		bash install.sh
		```
</Steps>

#### Common Maintenance Operations
- Check the deployment environment without installing Enterprise.
		```bash
		./install.sh --check-only
		```
- Clear all nodes after a failed deployment.
		```bash
		./full-cleanup.sh --env install.env --yes
		```
		
		:::caution[What difference it makes]
		This command wipes all Tier0 runtime data and database backups while keeping the VMs, operating system, and installed Docker software.
		:::

- A deployment report is generated after installation.
		```text
		runtime/install-reports/<timestamp>/deployment-report.md
		```
		
		:::caution[What you should do when **FAIL** appears in the report]
		Do not deliver the project if the report contains any **FAIL** item. Contact support first.
		:::

	<TabItem label="Edge">

	#### Requirements
	- Minimum 4-core CPU, 8 GB RAM, 100 GB disk
	- Ubuntu 24.04 or Windows 10/11 with Docker and Git
	#### Operations
	<Steps>
	1. Clone the Tier0-Edge repository from GitHub to your server and access the project.

		```bash
		git clone https://github.com/FREEZONEX/Tier0-Edge
		cd Tier0-Edge/deploy
		```

	2. Configure the parameters listed in the table below in `.env.default` according to your environment, and save the changes.
	
		```bash
		cp .env.default .env
		vi .env
		:wq!
		```
		:::note[Parameters to be configured]

		| Field | Type | Description | Example |
		|------|------|-------------|---------|
		| VOLUMES_PATH | string | Storage path for project data | `/srv/tier0/data` on Linux; `D:/tier0/data` or `/d/tier0/data` in Windows Bash |
		| ENTRANCE_DOMAIN/ENTRANCE_PORT | string | Tier0 access endpoint (IP/domain + port) | `192.168.1.10` / `8088` |
		| LANGUAGE | enum | zh-CN / en-US | `en-US` |
		| ADMIN_INIT_PASSWORD | string | Initial password for the admin user | A strong private password |
		| COMPOSE_PROJECT_NAME/PORT_OFFSET | string | Isolate multiple instances running on the same host | `edge_lab` / `100` |

		:::
	3. Run the installation script and check the installation status.

		```bash
		bash bin/install.sh
		bash bin/compose.sh ps # Check the status of the containers
		bash bin/compose.sh logs -f backend # Check the logs of the backend container
		curl -fsS http://127.0.0.1:8088/readyz # Check the readiness of the backend service
		```

		:::caution
		Do not edit `deploy/.env.runtime`; it contains generated secrets and resolved runtime values.
		:::
	4. Access Tier0 with the set endpoint and the default admin account:
		- Username: `tier0`
		- Password: The value of `ADMIN_INIT_PASSWORD` in `.env` or `tier0` if not set.
	</Steps>
