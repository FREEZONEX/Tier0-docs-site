Puedes operar datos de UNS mediante MQTT y APIs.

## MQTT
Los MQTT clients pueden conectarse al broker UNS con credentials generadas en Tier0.
:::note
Puedes usar MQTT clients como **MQTTX**, **MQTT Explorer** y **Node-RED** para conectarte al broker y publicar/suscribirte a messages.
:::
### Generar MQTT Credentials
En la pestaña **Edge** de Tier0, crea una nueva credential y guárdala.

### Conectar MQTT Clients

:::tip
Los siguientes clients se usan como ejemplos para mostrar cómo usar las credentials para conectarse al broker UNS.
:::

<Tabs syncKey="mqtt-client">
  <TabItem label="MQTTX">

1. Install and open <a href="https://mqttx.app/" target="_blank" rel="noopener noreferrer">MQTTX</a>.
2. Agrega una conexión con la información del broker UNS y las credentials generadas.
    ```json
    {
      "Host": "mqtt.tier0.dev",
      "Port": 8883,
      "Client ID": "<generated client ID>",
      "Username": "<generated username>",
      "Password": "<generated password>"
    }
    ``` 

  </TabItem>
  <TabItem label="MQTT Explorer">

1. Install and open <a href="https://mqtt-explorer.com/" target="_blank" rel="noopener noreferrer">MQTT Explorer</a>.
2. Agrega una nueva conexión con la información del broker UNS y las credentials generadas.
    ```json
    {
      "Protocol": "mqtt://",
      "Host": "mqtt.tier0.dev",
      "Port": 8883,
      "Username": "<generated username>",
      "Password": "<generated password>"
    }
    ``` 
3. Change the client ID to the credential ID in **ADVANCED** before connecting.

  </TabItem>
  <TabItem label="Node-RED">
      - Usa **Event Flow** - módulo de procesamiento de datos en Tier0 basado en Node-RED.
          1. Crea un **Event Flow** en **Flows** y empieza con un node `mqtt in`.
          2. Select the UNS broker as **Server** (same name as the flow) and set **Topic** to a UNS model in the node.
      - Usa una **instancia independiente de Node-RED**
          1. Instala y abre la instancia de <a href="https://nodered.org/docs/getting-started/local" target="_blank" rel="noopener noreferrer">Node-RED</a>.
          2. Agrega un server en el node `mqtt in` con la siguiente información.
          ```json
          {
            {/* under Connection */}
            "Server": "mqtt://mqtt.tier0.dev",
            "Port": 8883,
            "Client ID": "<generated clientId>",
            {/* under Security */}
            "Username": "<generated username>",
            "Password": "<generated password>"
          }
          ```
  </TabItem>
</Tabs>

### Probar conexiones
<Steps>
1. Asegúrate de que el client status sea normal.
2. Copia un topic de modelo UNS y publica un message en él mediante el client.
</Steps>

## API

### Lectura de datos en Cloud v2

Cloud v2 usa `https://<your-cloud-host>/openapi/v2` con `x-api-key`. Estos ejemplos leen registros de negocio y muestras temporales reales. No se aplican a Edge ni a Enterprise.

Primero llama a `POST /uns/metadata:find` con `{"kind":"collection","filter":{},"page":{"mode":"offset","page":1,"size":20}}`. El `data.items[].id` de la colección elegida es `collectionId`. El `id` devuelto por `records:find` es el `recordId` para las consultas de muestras. Ninguno de los dos es una ruta UNS.

#### Buscar registros: `records:find`

<Tabs syncKey="uns-api-language">
  <TabItem label="JavaScript">

```js
const base = process.env.TIER0_BASE_URL; // https://<your-cloud-host>/openapi/v2
const collectionId = process.env.TIER0_COLLECTION_ID;
const response = await fetch(`${base}/uns/collections/${encodeURIComponent(collectionId)}/records:find`, {
  method: "POST",
  headers: { "content-type": "application/json", "x-api-key": process.env.TIER0_API_KEY },
  body: JSON.stringify({"filter": {"status": "running"}, "limit": 20}),
});
const result = await response.json();
if (!response.ok || result.code !== 0) throw new Error(result.error?.code || result.msg);
console.log(result.data);
```

  </TabItem>
  <TabItem label="Python">

```python
import os
import requests

response = requests.post(
    f"{os.environ['TIER0_BASE_URL']}/uns/collections/{os.environ['TIER0_COLLECTION_ID']}/records:find",
    headers={"x-api-key": os.environ["TIER0_API_KEY"]},
    json={"filter": {"status": "running"}, "limit": 20},
    timeout=30,
)
response.raise_for_status()
result = response.json()
if result["code"] != 0:
    raise RuntimeError(result.get("error", result.get("msg")))
print(result["data"])
```

  </TabItem>
  <TabItem label="cURL">

```bash
curl --fail-with-body -X POST "$TIER0_BASE_URL/uns/collections/${TIER0_COLLECTION_ID}/records:find" \
  -H "content-type: application/json" \
  -H "x-api-key: $TIER0_API_KEY" \
  -d '{"filter": {"status": "running"}, "limit": 20}'
```

  </TabItem>
</Tabs>

#### Buscar muestras históricas: `samples:find`

<Tabs syncKey="uns-api-language">
  <TabItem label="JavaScript">

```js
const base = process.env.TIER0_BASE_URL; // https://<your-cloud-host>/openapi/v2
const collectionId = process.env.TIER0_COLLECTION_ID;
const response = await fetch(`${base}/uns/collections/${encodeURIComponent(collectionId)}/samples:find`, {
  method: "POST",
  headers: { "content-type": "application/json", "x-api-key": process.env.TIER0_API_KEY },
  body: JSON.stringify({"recordIds": ["record_123"], "from": 1792454400000, "to": 1792540800000, "filter": {"temperature": {"$gt": 20}}, "limit": 20}),
});
const result = await response.json();
if (!response.ok || result.code !== 0) throw new Error(result.error?.code || result.msg);
console.log(result.data);
```

`samples:latest` devuelve `data.series` con `{recordId, sample}` para cada registro; `sample` es `null` si no hay muestras. `samples:find` devuelve `data.items` y `data.pageInfo`. `from` y `to` son milisegundos Unix y delimitan `[from, to)`. Los filtros como `temperature` usan directamente los campos de negocio; los valores devueltos están en `data` de cada muestra.
