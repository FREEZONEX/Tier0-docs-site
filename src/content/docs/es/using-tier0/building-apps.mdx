Crea aplicaciones industriales personalizadas mediante conversaciones con IA. Pueden utilizar datos de fábrica e incluyen control de acceso por roles, gestión de versiones e implementación externa.

## Crear una aplicación Tier0

- Las carpetas solo clasifican aplicaciones.
- Se seleccionan automáticamente plantillas según tu prompt para reducir el tiempo de desarrollo.
- Hay prompts de plantilla para aplicaciones industriales comunes, como gestión de equipos, supervisión de producción y gestión energética.

### Escribir el prompt

Indica el objetivo, las funciones y si se necesitan datos externos.

- **Objetivo**: ¿Para qué sirve la aplicación?
```text
Crea una aplicación de mantenimiento para técnicos de fábrica.
```
- **Funciones**: ¿Qué debe hacer la aplicación?
```text
Permite supervisar equipos, enviar solicitudes de mantenimiento y seguir las reparaciones.
```
- **Datos**: ¿Necesita datos externos?
```text
Usa los registros de alarmas y el historial de mantenimiento de la collection xxx.
```

:::note
- Los datos simulados necesarios para iniciar la aplicación se generan y modelan en **Namespace**.
- El Agent debe conectar los datos externos y modelarlos en **Namespace**.
:::

:::tip[Crear aplicaciones más rápido]
- Usa las plantillas industriales de **Library** y adapta sus funciones.
- Usa prompts de plantilla.
- Usa las [Skills integradas de Builder](../../reference/embedded-builder-skills/).
- Si la conversación se alarga, usa `/clear` para limpiar el contexto o `/compact` para comprimirlo.
:::

### Control de acceso

Las aplicaciones usan control de acceso basado en roles (RBAC) para gestionar miembros y acciones permitidas.

- Si no se especifican roles, el Agent los genera según la lógica empresarial. Puede reutilizar roles compatibles de otras aplicaciones.
- Los roles de aplicación solo pueden asignarse a miembros del Workspace.
- Si el prompt indica expresamente que no se requieren roles, la aplicación se abre a todos los miembros.

:::tip[Asignar tus propios roles]
Define los roles y permisos en el prompt. El Agent los compara con los roles existentes y te consulta si hay conflictos.
:::

:::caution[Los roles son obligatorios en aplicaciones controladas por roles]
Para entrar desde **Launchpad** debes tener un rol de aplicación asignado. Incluso el propietario del Workspace necesita ese rol.
:::

### Gestión de versiones

- **Sin publicar**: Estado más reciente de la aplicación. Los cambios no afectan a otras versiones antes de la implementación.
- **Instantánea**: Guarda el estado en un momento dado; implementarla sustituye la versión actual.
- **Publicada**: Versión que está en línea.

Implementar la versión sin publicar actualiza la aplicación; implementar una instantánea vuelve a una versión anterior. Las instantáneas aparecen en la página de preview.

### Exportar a otros entornos

Desde **Preview** puedes exportar la aplicación para entornos de terceros o Tier0 Enterprise.

- **Descargar código fuente**: Para desarrollo adicional.
- **Exportar Bundle**: Para importarlo localmente en **Tier0 Enterprise**.

Para obtener el código de una instantánea, guárdala y después descárgala.
